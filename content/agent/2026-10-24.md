# 断流、披露与归属：运行时控制面必须显式化

今天最值得关注的不是某个新框架，而是三个容易被实现细节掩盖、却直接决定生产可靠性的控制面问题：SSE 断开后 Run 是否真的终止，工具何时对模型可见且何时允许执行，以及子 Agent 事件如何稳定归属到父 Run。三项更新都给出了可迁移的协议或状态设计，而不是只换接口。

检索窗口：2026-10-23 09:38 至 2026-10-24 09:19（Asia/Shanghai）。仅收录窗口内合并或正式发布、且与 10 月 23 日已归档内容不重复的更新。

## 1. Google ADK：修复 ASGI 2.4 下 /run_sse 断连后 Agent 仍在后台运行

- **来源**：[Google ADK commit](https://github.com/google/adk-python/commit/1fbe9e034506a0a9a03039a68e822fb1b787a165)
- **日期**：2026-10-23
- **精读建议**：**必读**

### 核心变化

**来源结论：** 在 Uvicorn 的 ASGI 2.4 路径中，Starlette 的 `StreamingResponse` 不再自行监听断连；客户端断开后，`send()` 还可能静默返回而不抛异常。因此 `/run_sse` 的生成器不会自然收到取消，Agent 会继续产出事件和执行工具。补丁抽取统一的断连监视器，监听 `request.receive()` 的 `http.disconnect`，设置 abort signal、唤醒等待步骤并取消生产任务。新增测试验证断连后持久化 `INVOCATION_ABORTED`，同时为悬空工具调用补齐终止结果。

相比“依赖流写失败触发取消”的既有做法，这次把**传输断连**显式映射成**运行时取消事件**，并要求最终状态可持久化、可恢复读取。

### 工程价值、证据与局限

**工程价值：** 它修复的是资源和副作用泄漏，而不只是前端停止转圈：断开的浏览器不会让模型、工具和计费继续无主运行。测试同时覆盖权威终态与未闭合工具调用，说明修复目标是状态收敛，不只是取消协程。

**局限：** 证据来自单一 ASGI/Uvicorn 路径和单进程测试；多进程或分布式执行仍需要把取消信号写入共享状态。已经开始的外部工具副作用也不会被自动回滚，仍需幂等键、补偿或租约。该修复目前是主分支提交，不等同于已进入稳定发行版。

### 适用场景与工程推断

- **Agent 会话 / SSE 收敛：** 不要把 `send()` 失败当作唯一断连检测；入口层应独立监听 disconnect，并写入可查询的权威终态。
- **工具确认与续跑：** “UI 离开”不一定等于“用户取消”。若产品支持稍后重连，应把 `detached`、`cancel_requested`、`aborted` 分开，而不是统一为断连即杀。
- **状态恢复：** 重连客户端应以持久化的 `INVOCATION_ABORTED` 为准；本地 `EventSource.onerror` 只能表示视图失联。
- **工具执行：** 取消后必须封口未完成 tool call；外部副作用用 invocation/tool-call 幂等键防止恢复时重复执行。

## 2. Deep Agents Code 0.2.1：按 skill 延迟披露 MCP 工具

- **来源**：[Deep Agents PR #7010](https://github.com/langchain-ai/deepagents/pull/7010)
- **日期**：2026-10-23（合并，并列入 0.2.1 发布）
- **精读建议**：**必读**

### 核心变化

**来源结论：** MCP server 可用 `skillOnly: true` 选择延迟披露；工具 schema 不再一开始就进入模型上下文和工具清单，只有读取对应 skill 或显式 pin 后，skill 的 `metadata.include_tools` 所列工具才出现。原有过滤、审批、hook 和超时仍保留，且适用于主 Agent、自定义 sub-agent 与通用 sub-agent。未选择该模式的 server 仍保持 eager 行为。

相比“启动时发现全部 MCP 工具，再靠 prompt 提醒模型少用”的做法，这次新增的是**模型可见性的结构化门控**：skill 成为工具集合的披露边界。

### 工程价值、证据与局限

**工程价值：** 它直接缩小长会话中的工具 schema 占用和误选面，并让同一 MCP server 面向不同任务只暴露最小工具集。PR 已合并且进入 0.2.1 发布；实现保留审批链，避免因延迟披露绕开既有执行控制。

**局限：** 这只是**披露门控，不是权限边界**。MCP 连接和工具发现仍在启动期发生；延迟连接和 server group 不在本次范围。skill 已进入上下文后工具会持续可用，长会话压缩、撤销和 sub-agent 继承仍要由应用明确管理。

### 适用场景与工程推断

- **Tool Gate：** 将工具状态至少拆成 `hidden → disclosed → authorized → executed`；读取 skill 只允许推进到 `disclosed`，真正执行仍走用户确认和策略审批。
- **Agent 会话：** 把 skill 激活记录进权威会话状态，恢复时按记录重建工具面；不要只依赖被压缩过的 prompt。
- **sub-agent 隔离：** 子 Agent 只继承任务所需 skill 和工具集合，而不是父 Agent 的完整工具表。
- **上下文治理：** 用 server 的 skill-only 开关定义默认隐藏，用 skill 的精确 include list 定义最小暴露；两者共同决定披露范围。

## 3. AG-UI / Mastra：把 supervisor 委派映射为可归属的子 Agent 生命周期

- **来源**：[AG-UI PR #3153](https://github.com/ag-ui-protocol/ag-ui/pull/3153)
- **日期**：2026-10-23
- **精读建议**：**必读**（若正在做多 Agent UI、恢复或用量归集）

### 核心变化

**来源结论：** Mastra adapter 新增可选的 attributed 模式：默认仍隐藏子 Agent；开启后会发出 `SUBAGENT_STARTED`，把子 Agent 的文本、推理和工具事件标记为 `subagentRunId`，再以 `SUBAGENT_FINISHED` 或 `SUBAGENT_ERROR` 收口。嵌套委派使用层级 ID；暂停后恢复会重新宣布同一 ID；运行结束、错误、停止或暂停前，开放的子调用按最深层优先关闭。子模型用量也汇入顶层 `RUN_FINISHED`，并尝试跨暂停/恢复只计一次。

相比只把所有 token/tool 事件混入父流，这次新增的是**父子归属、生命周期闭合和用量汇合的一套事件语义**，UI 不必再从 tool 名或消息顺序猜测哪个 Agent 正在工作。

### 工程价值、证据与局限

**工程价值：** 明确的父子 ID 和终止事件使并发 UI 投影、审计、取消传播与成本归集都可确定实现；最深层优先关闭还能减少父节点先终止、子事件随后到达造成的悬挂。PR 提供真实 Mastra 流测试和用量测试，而不只是类型声明。

**局限：** 实现面向 Mastra supervisor，尚不覆盖 Mastra networks 或 workflow-as-tool。PR 还记录了 Mastra 1.79 在暂停前后可能重复报告 supervisor usage 的已知问题，因此“跨恢复恰好计一次”仍需要消费端用稳定 ID 去重。隐藏子 Agent 或省略其 tool result 只是线协议裁剪，不应被当作权威状态删除。

### 适用场景与工程推断

- **多 Agent 编排：** 子 Run 使用层级稳定 ID，并把 `parentRunId`、`subagentRunId`、`attempt/epoch` 分开；同一 ID 的恢复重宣布不能被 UI 当成新任务。
- **流式事件收敛：** 对暂停、停止和父 Run 终止建立确定的关闭顺序；优先关闭最深层子调用，再关闭父调用。
- **UI 投影：** 前端以归属字段分栏或折叠子 Agent 活动，不再从消息内容推断；重放时按稳定 ID 幂等合并。
- **状态与计费：** 用终态事件或稳定调用 ID汇总 child usage，避免累积型 step usage 在恢复后重复相加；wire 上 omit 的内容仍保留在服务端权威记录。

## 今天可尝试的工程改进

1. **补一组“断流不等于终止”的故障注入测试。** 在首个 token、工具确认等待、工具已启动和子 Agent 运行中四个阶段强制断开 SSE，分别断言 Run 的持久化状态、未闭合 tool call、外部副作用和重连后的 UI 投影是否收敛。
2. **把控制面拆成两张显式表。** 一张记录工具的 `disclosed/authorized/executed`，另一张记录 Run 树的 `parent/id/epoch/status/usage`；验证上下文压缩、暂停恢复和并发子 Agent 下，这两张表能否独立重建模型工具面与 UI。
