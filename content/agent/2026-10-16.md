本期三篇研究共同指向一个问题：Sub-agent 能否核验同伴信息、维护跨 Agent 的权威记录，并完整执行锁释放、交接和归档等收尾协议？原简报没有收录新的 SSE 传输层更新。

## A²-Failures：私有状态下的协作失败

**日期：v1 提交于 2026-10-14，10 月 15 日进入新论文列表。精读判断：必读。**

### 核心变化

以往多 Agent 研究通常默认共同 orchestrator、共享工作区和共同目标。这项研究让每个 Agent 代表不同个人或组织，各自拥有私有文档、凭证、工具和权限，唯一通信路径是 A2A 消息协议，利益可以一致、部分一致或竞争。

作者分析 488 个场景、超过 2,500 次运行，得到覆盖发现与委派、记录一致性、验证、行为与忠实性的 20 类失败。原简报记录：Agent 很少主动查询可用同伴，在没有协议强制时不主动核验其他 Agent 的主张。

### 工程价值与证据

论文将评测拆为三个独立层次：

- L0：真实工具调用、返回和状态写入。
- L1：最终产物是否正确。
- L2：过程中是否泄密、伪造、越权，或违反所代表对象的利益。

作者还观察到过期授权仍被执行、请求尚未结束便提交结果、上下游记录失去 lineage，以及声称已批准 / 已归档但环境没有对应记录的情况。

### 工程推断与局限

Agent 消息应作为 claim，不能直接变成权威状态。peer_completed 应绑定可验证 artifact、tool receipt 或 environment revision；委派协议记录 principal_id、authority_scope、task_version、parent_event 和 evidence_refs。SSE / UI 应分开展示执行事实、产物状态和合规状态。

失败标签部分依赖分析 Agent 和人工复核；模型与 harness 未完全解耦，频率不能直接外推为线上事故率。

## CLASHarness：把协议收尾纳入验收

**日期：v1 提交于 2026-10-13，10 月 15 日进入新论文列表。精读判断：必读。**

### 核心变化

它要求 Agent 根据环境证据解决冲突，并执行真实状态修改：撤销权限或错误配置、释放共享锁、完成 sub-agent handoff，以及在有效时间窗内完成确认和交接。600 个多轮任务通过真实参考轨迹生成检查器。

### 工程价值与证据

原简报记录：15 个模型在只需调查冲突时任务通过率为 28.1%；要求修改系统状态时降至 11.0%；要求完整完成协议时为 4.4%。锁释放和任务交接等收尾动作、时间窗同步是明显薄弱环节。

### 工程推断

把收尾从自然语言 TODO 改为 runtime 管理的 barrier。以下是工程建议，并非论文原始协议：

```text
result_verified
→ artifact_committed
→ locks_released
→ authority_revoked
→ handoff_acknowledged
→ branch_closed
```

只有满足业务要求的 barrier，父 Run 才进入 completed；否则保持 closing 或 blocked，重连后继续从权威状态恢复。

### 局限

场景主要以日志和工作区轨迹模拟异步协作，并非真实实时聊天；部分评分依赖 LLM judge，而且缺少无冲突基线。

## Skill：静态冲突不等于运行时伤害

**日期：v1 提交于 2026-10-13，10 月 15 日进入新论文列表。精读判断：选读。**

### 核心变化与证据

论文检查 575 个 Skill，确认 1,182 个文档、代码、配置和环境之间的契约冲突；随后对 49 个可执行任务进行 Original Skill 与 Fixed Skill 成对重放。

约三分之二 Skill 存在冲突，但静态问题数量不能预测实际伤害。差异主要发生在暴露之后：有的模型继续遵循错误说明，有的会绕过或修复问题。原简报记录，修复带来的得分提升在三个模型上分别为 0.136、0.085 和 0.023。

### 工程推断与局限

发布 Gate 应结合冲突类型、可达执行路径、目标模型是否采纳、verifier 是否恢复，以及 paired replay 的结果。优先处理文档承诺了代码不支持行为的冲突。

49 个任务被刻意设计为触发冲突，不能代表自然暴露概率；只覆盖三个模型和容易构造确定性 verifier 的任务。

## 带回开发现场

1. 模拟“结果已返回，但锁未释放或交接未确认”，检查父 Run 是否过早显示完成。
2. 对一个 Skill 做修复前后 paired replay，分别记录 exposed、followed、recovered 和 final_failure。
