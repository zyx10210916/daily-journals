本期最值得关注的变化是：Agent 编排开始从消息驱动的自由协作转向两类可验证结构——带责任归属的承诺状态机，以及受依赖关系约束的任务完成度。两者都能映射到 Tool Gate、同一 Run 续跑、SSE 投影和 sub-agent 结果汇合。

## RCM：责任不会随委派消失

**来源日期：2026-10-15，v1。精读判断：必读。**

### 核心变化

过去的多 Agent 框架通常只记录任务由谁执行，RCM 新增的是有生命周期、有版本、有验收条件的双边承诺。

委派者不会因任务已经交给子 Agent 而解除责任，仍须监控、验证结果，并在失败时恢复或重新委派。协议显式定义 delegate.propose / accept、commitment.revise、outcome.submit / verify 等操作；修改只有经双方接受的新版本才能生效。

### 工程价值与证据

作者在 AIME25、HumanEval、Claw-Eval、Claw-Live 上，以相同 Agent、工具分配和预算比较多种编排方式。原简报记录：RCM 在多数设置中表现最佳，同时支持动态工作流与分布式监控 / 恢复。

可迁移的运行时对象包括：

```text
commitment_id / version
delegator / delegatee
scope / permissions / resource_budget
activation_condition / completion_criterion
status / outcome_evidence
supporting_commitments[]
```

### 适用场景——工程推断

- **Tool Gate：** 将待审批调用映射为 Requested，用户确认后进入 Agreed。续跑绑定同一 run_id、commitment_id 和 version。
- **SSE：** 传输 commitment.revised、outcome.submitted、outcome.verified 等事实事件；UI 依据验证状态显示完成。
- **Sub-agent：** 父 Agent 可以继续拆分任务，但在支撑承诺验证完成前仍保持责任。
- **失败恢复：** 子承诺失败时关闭、替换受影响分支，避免无条件整条 Run 重启。

### 局限

这是基于生命周期规则的责任约束，不是分布式共识或 exactly-once 协议。生产环境仍须解决幂等、事件乱序、重复提交和长期承诺图的压缩；尚未证明超大规模承诺图的调度成本。

## WEAVE：局部成功不等于整体进展

**来源日期：2026-10-15，v1。精读判断：必读，重点阅读 Graph Credit。**

### 核心变化

WEAVE 将真实代码演进任务组织成依赖 DAG，并提出 Graph Credit：一个节点即使通过自己的测试，其有效完成度也不能超过任何上游依赖的完成度。

作者称普通测试通过率产生的虚高为 phantom credit。Graph Credit 由可执行测试结果和 DAG 元数据计算，不依赖历史提交顺序、补丁相似度或 LLM 裁判。

### 工程价值与证据

原简报记录：在 8 个模型、2 种 Agent scaffold 的 16 个配置中，普通测试完成度比依赖约束后的得分高出平均约 10.5 个百分点，范围为 7.2–16.8 个百分点。这个差值是基准内的诊断信号，不能直接等同于线上 UI 的错误率。

### 适用场景——工程推断

- Task Gate 中，local_success 不直接升级为 task.completed；先检查前置节点。
- Sub-agent 可以提交局部结果，但父节点应在依赖闭包满足后收敛。
- SSE / UI 分离 node_local_passed 和 node_effectively_completed，后者根据 DAG 推导。
- 状态恢复时，从事件重算有效完成度，避免持久化易失真的进度百分比。
- UI 同时呈现“局部完成”和“因依赖阻塞”。

### 局限

方法要求可靠的依赖 DAG 和节点级验证器。无法归因或归因模糊的测试被排除在节点评分之外。一般办公或研究任务如果缺少明确验收器，迁移价值会下降；递归取最小值也不能替代具体业务的依赖语义。

## 带回开发现场

1. 为 Tool Gate 增加版本化承诺：审批记录绑定 run_id、gate_id、proposal_hash、version。规范化后的动作契约发生变化时重新检查授权。
2. 在任务 UI 中同时计算 local_status 和 effective_status，注入上游失败、SSE 乱序以及子 Agent 提前返回，观察整体完成态。
