## Deep Agents Code 0.1.87：无头任务可以显式续跑，失败不再伪装成新线程

**来源：LangChain / Deep Agents；发布：2026-10-20；核验：2026-10-21。**

[查看发布说明](https://github.com/langchain-ai/deepagents/releases/tag/deepagents-code%3D%3D0.1.87) · [线程续跑实现说明](https://github.com/langchain-ai/deepagents/pull/7011) · [空闲压缩实现说明](https://github.com/langchain-ai/deepagents/pull/6956)

### 核心变化——来源结论

dcode -r <thread-id> -n "..." 现在可在非交互模式恢复既有会话。恢复会带回对话历史、Agent 和上次使用的模型；显式覆盖模型除外。实现要求原工作目录和会话标志兼容，并在无效或不兼容时直接报错，不再像旧行为那样忽略 -r、静默创建新线程。安静模式会把线程 ID 输出到 stderr，便于脚本保存并用于后续调用。

同一版本还加入可选的空闲压缩：当上下文超过配置阈值，并进入已知提示缓存窗口的最后 20%（最多提前 120 秒）时，运行既有的 offload 操作，把旧上下文摘要并归档；繁忙、正在输入、存在排队输入或缓存窗口未知时跳过，用户可以取消。该功能默认关闭。

### 工程价值、证据与局限

工程价值不在命令行本身，而在三个可迁移的恢复约束：恢复键必须显式暴露；恢复前校验创建模式、工作目录和会话参数；恢复失败必须 fail closed，不能退化成新会话。这样可避免调度器把新线程误认为原任务的延续，进而丢失确认记录、工具结果或审计关联。

证据方面，续跑改动合并前通过了仓库显示的 94 项检查；发布说明与合并记录能确认行为已经进入正式版本。但这不是生产可靠性评测，没有给出长时间故障注入、并发恢复或外部副作用去重数据。

限制也很具体：无头续跑只支持由非交互模式创建的线程，不支持交互线程；它恢复的是会话历史、Agent 和模型，不等于恢复同一个运行中 call stack，也没有证明工具副作用具备 exactly-once。空闲压缩会丢细节，摘要本身消耗 token，官方明确说明净节省和缓存复用都不保证。

### 适用场景——我的工程推断

- **Agent 会话与定时任务：** 将 thread_id、创建模式、workspace identity、agent revision、model override 和 session flags 作为一个可校验的 resume descriptor。调度器续跑前先读取并比对，而不是只传一个裸 ID。
- **Tool/Task Gate：** thread resume 不应自动释放待确认动作。恢复后重新加载 gate_id、绑定的 action digest、决议状态和过期策略；动作或环境变化时重新申请确认，而不是沿用旧许可。
- **状态恢复：** 把“找不到线程”“线程不兼容”“线程可恢复但工具结果未知”分成不同终态。前两者拒绝续跑，后一种进入 reconciliation，先核对外部系统再决定是否重试。
- **SSE 与 UI 投影：** 恢复后先发布一条带原 thread_id、旧 stream epoch 和新 connection epoch 的 authoritative resume event；客户端清空连接级临时状态，但保留由事件日志确认的任务状态。原发布没有给出 SSE 协议，这部分是设计推断。
- **上下文管理：** 缓存到期前压缩应视为有损状态迁移，保存 summary_version、source range 和 archive pointer；关键确认、工具结果和未解决错误不要只存在摘要里。

### 是否值得精读

**选读。** 如果你在做 CLI Agent、批处理 Agent、队列消费者或定时任务续跑，值得精读线程恢复 PR 中的拒绝条件与脚本接口。若重点是断流重放、外部写操作的 exactly-once 或跨进程并发恢复，这个版本只给出边界启发，没有完整协议。

## 带回开发现场

1. 为现有 resume API 增加一次“身份错配”故障注入：换工作目录、Agent 版本或会话标志后尝试续跑，确认系统明确拒绝，且不会创建一个新的 run/thread 冒充成功。
2. 在待确认工具调用和已完成外部写入两种状态分别触发恢复：检查前者是否仍需同一 action digest 的有效批准，后者是否进入副作用核对，而不是重新执行工具。
